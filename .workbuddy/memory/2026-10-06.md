## 本次修复：blink-cmp spec 报 module 'coc-sort' not found

改名后首启报错（lazy.nvim 弹窗 `Failed to load plugins.blink-cmp`），两个叠加根因：
1. **旧绝对路径**：blink-cmp.lua 还指向 `~/.config/nv/...`（插件目录、词典路径），随改名全部失效。
2. **lazy.nvim spec 加载时序（真坑，headless -u NONE 测不出来）**：
   `require("lazy").setup()` 内**同步**导入 `lua/plugins/*.lua` spec 文件，此时在 spec 里
   `vim.opt.runtimepath:prepend(dir)` 后立刻 `require(...)`，Neovim 对 rtp→package.path
   的更新是**异步调度**的，还没生效 → 找不到模块。报错里 package.path 只剩 luajit 默认项可证。

**修复**（`~/.config/nvim/lua/plugins/blink-cmp.lua` 顶部）：
```lua
local plugin_dir = "/home/a/.config/nvim/coc-sort.nvim"
vim.opt.runtimepath:prepend(plugin_dir)
local lua_dir = plugin_dir .. "/lua"
if not package.path:find(lua_dir, 1, true) then
  package.path = package.path .. ";" .. lua_dir .. "/?.lua;" .. lua_dir .. "/?/init.lua"
end
local csort = require("coc-sort")
```
显式 package.path 注入是同步生效的，不依赖 nvim 的异步更新。词典路径同步改为
`~/.config/nvim/dict/10k.txt`。

**验证**：33/33 功能 + 15/15 接线（新增 package.path 注入断言）全绿；
`nvim --headless` 用真实配置启动，`STARTUP_DONE` 且 blink 报错消失
（尾部 mason "luacheck 安装中断" 提示与本次无关，纯 +qa 也复现）。

## Dashboard 框线闭合 + 启动耗时优化（本轮）

**框线没闭合**：banner 用 snacks `terminal` 区块（shell echo）。顶/👾/底都是 57 列，
只有日期行因 `$(date '+%Y-%m-%d %H:%M')` 只有 16 字符、而手工补的空格数不对 → 46/63 列，右边框错位。
修法：`echo` 全改 `printf`，日期行用 `printf '  │         %-44s│\n' "$(date '+%Y-%m-%d %H:%M')"`
（12 前缀 + 44 定宽 + 1 边框 = 57），日期宽度变化也自动闭合。
⚠️ 坑：用 bash 写 lua 脚本改文件时，`$(date ...)` 会被 shell 提前展开成字面时间 —— 必须用 Edit 工具写入。

**启动耗时 260ms → 58.7ms**（`nvim --headless --startuptime` 实测），三处根因：
1. `init.lua:11 → require("config.lsp")`，而 `config/lsp.lua` 首行
   `require("blink.cmp").get_lsp_capabilities()` → 启动时连带加载 luasnip + 全部片段（176ms，占 68%）。
   修法：改成内联与 blink `sources/lib/init.lua:301` 完全等价的静态 capabilities 表，
   再挂 `User LazyLoad`（data==blink.cmp）把真实值合并回同一张表 → 功能零损失。
   （nvim 在 client.lua:437 会 `force` 合并 protocol 默认能力，所以静态表安全）
2. `plugins/luasnip.lua` 用 `from_lua.load(config/snippets)` **一次性解析全部片段 = 174ms**；
   参考 `~/.config/oldnvim/lua/plugins/luasnip.lua` 改 `lazy_load`（0.8ms），
   并去掉 `event = "InsertEnter"`（oldnvim 也是注释掉的）——首次插入模式成本 190ms → 13.3ms。
3. `config/lazy.lua` 的 `opts.colorscheme = "catppuccin-mocha"` 与实际主题不符 →
   启动时先加载整套 catppuccin（~4.5ms）再被 cyberdream 覆盖；改成 `"cyberdream"`。
   另确认 `vim.loader` 已启用（字节码缓存正常）。

排查手法（可复用）：`--startuptime` 找 self 最大的 require → 用
`vim.uv.hrtime()` 冷测各步骤（require / lazy_load / load）定位真凶 ——
注意 startuptime 的"self"归属偶尔不准（本例把 from_lua.load 记到了 from_vscode 头上）。

## Noice / blink 命令行补全优化

问题：`:mess` 不显示 `:messages`，反而出现 `Property make/menu/mode...`；上下方向键不能轮询候选。

根因：
1. blink 的 `cmdline` preset 没绑 `<Up>/<Down>`，方向键被原生处理（历史/光标）。
2. 命令行补全默认 sources 是 `{ "buffer", "cmdline" }`；全局 `fuzzy.sorts` 用了 coc-sort comparator，
   会把命令按词频/历史重排，前缀匹配（如 mess→messages）被挤到后面甚至不可见。
3. cmdline source 把所有项的 `kind` 固定设为 `CompletionItemKind.Property`，
   加上全局 draw 列含 `kind`，菜单里每项前面都带个 "Property"， clutter 且占宽。

修法（`blink-cmp.lua` 加 `cmdline` 块）：
- keymap preset=cmdline，补 `<Up>=select_prev`，`<Down>=select_next`。
- `cmdline.sources.default = { "cmdline" }`（去掉 buffer）。
- `cmdline.fuzzy.sorts = { "exact", "score", "sort_text", "kind", "label" }`（绕开 coc-sort）。
- `cmdline.completion.menu.draw.columns = { { "label", "label_description" } }`（去掉 kind/source_name 列）。

> 纠错：`fuzzy` 不是 cmdline 模式配置的合法字段（排序只能全局配），放进去会报
> "Unexpected field in configuration!"。已删除。前缀匹配本就由全局 `fuzzy.sorts` 的
> coc-sort comparator（tier 0 优先）保证，`:mess → messages` 自然排最前，无需在 cmdline 里再覆盖。
